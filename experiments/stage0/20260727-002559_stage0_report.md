## 3. 关键修复记录（blocker 闭环）

- **现象**：`baseline_radarpillar` 落袋 resbag `cfg.yaml` 的 Cyclist 为 8-anchor（2 sizes / bottom -0.72），而 ckpt head 为 6-anchor（conv_cls=18）。`load_params_from_file` 逐键 shape 过滤会**静默跳过 dense_head 6 键** → 锚点 AP 成垃圾值（不崩、silently corrupt）。
- **根因**：resbag 误存了 stale 8-anchor cfg；ckpt 真训练 cfg = `tools/cfgs/model/vod_models/radarpillar/vod_radarpillar_rot.yaml`（Cyclist 1 size [[1.76,0.6,1.73]] / bottom -0.6，train.log L95 印证）。
- **处置**：① 阶段0 baseline val 直接用 `vod_radarpillar_rot.yaml`（不动冻结 resbag cfg）；② `experiments/YAML/a0-a3.yaml` 同继承 8-anchor，已统一改 Cyclist 锚为 6-anchor（=rot.yaml），保证 a1 可无跳权复用 baseline ckpt、且 a0-a3 sweep 与 baseline 同锚（注意力为唯一变量）。
- **验证**：load-smoke a1↔ckpt 转 CLEAN（0 mismatch）；a0-a3 锚签名=6/loc；build_check 全 PASS；git diff 仅 Cyclist 锚块（8+/20-）。fpn/mdfen resbag cfg 验 CLEAN，原样使用。

## 4. 锚点现象（供后续阶段参照）

- 简单 PointPillar 基线（0.18M）mAP 反而**最高**；RadarNeXt-FPN/MDFEN 参数 6–9× 却在 Car/Ped 偏低、仅 Cyclist 持平。提示 backbone 容量/neck 的增益需在 RPiN 自身贪心链（同协议、同锚）上重测，base 间横比仅作量级参照（架构/口径不同）。
