# 模型定型与部署前工作计划

**总目标**：从已训/待训模型中定型 3~4 个基准，打通 detect + tracker 全链，产出可支撑部署决策的证据链。
**数据背景**：MSR 场地数据（小规模标注）训练；泛化验证对象为同场地不同时段/路线的未标注数据；部署目标 ZU3EG（FPGA 路线，B400/B800，5EV B1600 备选）。

**执行顺序**：P0 → P1（P5 并行） → P2 → P3 → P4

---

## P0 · 可信度地基（split 审计 + 过拟合验证）

**任务与目的**：验证现有 AP 分数真实可信（无数据泄漏、非单次运气）。它是后续一切选型的地基——地基不稳，后面所有结论作废。

**现状输入**：MSR 小规模标注训练；split 划分方式未审计。

**Pipeline**：

1. **审计 split 划分**
   - 做什么：检查 train/val/test 边界是否按录制序列划分（同一序列的帧只能落在一个 split）
   - 符合：按序列划分 → 进 step 2
   - 不符合：帧级随机划分（相邻帧几乎相同，val AP 虚高）→ 重划 split、重评已训模型，重新过本步

2. **定验证协议**
   - 做什么：选定留序列 CV（每次留一条序列做验证、其余做训练，轮换汇总）或固定 holdout（固定留出几条序列）；入选模型补 2~3 个随机种子重训
   - 符合：协议确定且落盘（P2 泛化评估直接共用）→ 进 step 3
   - 不符合：序列数太少不足以轮换 → 退回固定 holdout + 多种子口径

3. **复核关键增益**
   - 做什么：在新口径下重算「Pedestrian 43→68」一类增益，判断是架构真收益还是泄漏/运气
   - 符合：CV 口径增益 ≥ +15pt → 认定为架构收益，进 P1
   - 不符合：增益缩水至 < +15pt → 降级为待定，选型不据此加分（不阻塞 P1）

**阶段出口预期**：各模型「AP 均值 ± 方差」可信分数表；split 干净 + 协议落盘。

---

## P1 · 基准选定（准确 / 轻量 / 兼顾 × 部署门禁）

**任务与目的**：定稿 3~4 个基准（准确档 / 轻量档 / 兼顾档各有所属），且每档过得了部署门禁——AP 高但量化掉点大的同样不可部署。

**现状输入**：已训 11 个中初筛出「综合占优、无更优替代」的几个——双优 `msr_centerhead3d_trunk`（3D 91.05 @ 5.49G FLOPs / 0.27M 参数，全面优于其 full 版 90.70 @ 20.8G）；轻量 `msr_repdwc32`（0.06M / 2.65G，Pedestrian ~31 硬伤）；折中 `msr_repdwc64`（0.18M / 4.24G / AP 82.3）；anchor 基线 `msr_radarpillar`（83.3）；上界参照 RadarNeXt 原版（92.1 @ 35.5G，ZU3EG 资源预计超标，不入围）。另有未训 28 变体待门禁筛短名单。

**Pipeline**：

1. **定 z 消费决策**（先于一切筛选）
   - 做什么：与 tracker 侧确认量测是否消费 z（目标高度）
   - 符合：结论明确落盘 → 进 step 2
   - 不符合：暂无法定 → 默认消费 z（ch2d 系无 z 回归、3D AP 恒 0，整系淘汰），后续推翻再回补并记录在案

2. **门禁初筛**
   - 做什么：按「3D mAP / 弱类（Pedestrian、Cyclist）/ FLOPs / PARAMs / ZU3EG 资源」过滤已训 11 个；未训 28 变体只按门禁筛短名单补跑，不全量
   - 符合：每档 ≥1 个候选存活 → 进 step 3
   - 不符合：某档空缺 → 从 28 变体补跑该档 2~3 个，再过本步

3. **INT8 量化测试**
   - 做什么：候选逐个做训练后量化（PTQ），记录 AP 掉点
   - 符合：掉点 ≤ 阈值（3D mAP 掉 ≤ 2pt）→ 保留
   - 不符合：掉点超阈 → 淘汰，回 step 2 补位

4. **定稿三档**
   - 做什么：综合门禁结果定稿，准确 / 轻量 / 兼顾三档覆盖齐
   - 符合：三档各有定稿且每个含 INT8 掉点数据 → 完成
   - 不符合：档间高度重复（同一模型占双档）→ 收缩为 3 基准，记录取舍

**阶段出口预期**：选型矩阵 + 定稿 3~4 基准清单。

## P2 · 泛化：换时段/路线还行不行

**任务与目的**：模型是拿场地某时段的标注数据训练打分的；部署面对的是同场地别的时段/路线数据，没标注，算不了 AP。所以分四步：先看数据变没变，再看模型行为变没变，再不用标注挑错，最后标几百帧出真分数。

**现状输入**：待验证数据 = 同场地不同时段/路线的未标注录制段；评估脚本与 P0 共用。

**Pipeline**（新数据来了整段过一遍）：

1. **看数据变没变**
   - 做什么：各录制段 vs 训练数据，比每帧点数 / RCS / doppler / 距离分布，算个差异分值（PSI/KS 均可）
   - 符合：差不多 → 进 step 2
   - 不符合：某段差得多 → 记为可疑段，优先送 step 4

2. **看模型行为变没变**
   - 做什么：各段过模型，检出数 / score 分布 / 类别占比 / 框尺寸，和 val 比
   - 符合：和 val 一致 → 进 step 3
   - 不符合：某段异常 → 结合 step 1 定位：是数据变了还是模型自己不稳

3. **不用标注挑错**
   - 做什么：查框速度 vs 框内点 doppler、航迹抖不抖、静止目标是否零速；再让几个基准模型互相对答案，分歧大的地方就是可疑处
   - 符合：物理错误少、模型间分歧小 → 判稳
   - 不符合：错误集中在某段 → 该段单独出报告，查是标注、传感器还是场景真变了

4. **标几百帧，出真分数**
   - 做什么：挑 2~3 段 × 几百帧（最可疑 1~2 段 + 正常 1 段），模型预标注 + 人工修正，算 AP
   - 符合：golden AP 和 val AP 差 ≤ 3pt → 判稳
   - 不符合：某基准差 > 3pt → 泛化存疑，回 P1 换档内备选

**阶段出口预期**：分段排查报告（哪些段正常/可疑）+ golden set AP；每个基准落一个「稳 / 存疑」。

## P3 · 检测器误差模型（tracker 参数化依据，前置于 tracker 调参）

**任务与目的**：把每个基准的「错误规律」量化成参数表——tracker 的量测噪声、门限、确认逻辑直接从中取初值，替代拍脑袋调参。

**Pipeline**：

1. **score 校准**
   - 做什么：画可靠性图、算 ECE（校准误差，衡量 score 偏离真实命中概率的程度），检验 score ≈ 真阳概率
   - 符合：ECE 低，score 可直接当确认概率 → 进 step 2
   - 不符合：校准差 → 记录分桶修正映射，tracker 消费修正后 score

2. **条件误差统计**
   - 做什么：按「类别 × score 档 × range 档」分桶，统计位置/速度/尺寸误差的均值与协方差 → tracker 噪声 R 阵与 gating 阈值
   - 符合：每桶样本量 ≥ 30 → 桶数据可用
   - 不符合：某桶样本不足 → 合并相邻桶，记录合并口径

3. **FP 特性统计**
   - 做什么：统计假阳性率 vs score / range → M-of-N 确认门限（N 帧中 ≥ M 帧命中才确认航迹）
   - 符合：FP 集中在低 score / 远距离 → 门限可按分布参数化
   - 不符合：FP 分布均匀无规律 → 取保守门限，tracker 侧靠航迹逻辑兜底

4. **落盘**
   - 做什么：全部统计按固定格式写成 per-model error model（yaml），统计口径随文档落盘
   - 符合：全部基准覆盖 → 完成
   - 不符合：某基准缺数据 → 单独回补，不阻塞其他基准

**阶段出口预期**：每基准一份 error model（yaml）+ 统计口径文档。

---

## P4 · Tracker 打通 + 量化指标

**任务与目的**：真实检测输出（非 GT 注入）接入 tracker，端到端跑通并出双层指标（学术 MOT 指标 + 量产指标），确定 tracker 参数基线。

**Pipeline**：

1. **端到端打通**
   - 做什么：基准模型检测输出 → tracker → 航迹落盘，全链一键复现
   - 符合：全部基准无人工干预跑通 → 进 step 2
   - 不符合：某基准输出格式不兼容 → 加适配层（不改模型）

2. **指标双口径**
   - 做什么：val + golden set 双口径算 MOT 层（MOTA / MOTP / IDS / fragmentation，可选 IDF1 / HOTA）+ 量产层（起批时延、虚假航迹率、航迹纯度/持续分布、断裂-重捕获）
   - 符合：指标一键复现 → 进 step 3
   - 不符合：指标依赖手工步骤 → 先流水线化再继续

3. **参数敏感性扫描**
   - 做什么：gating / score 门限 / M-of-N 扫描，初值取 P3 error model
   - 符合：找到稳定参数区间（非尖峰最优）→ 定参数基线
   - 不符合：性能对参数高度敏感 → 回 P3 检查误差模型是否失真

**阶段出口预期**：双口径指标报告 + 最优基准的 tracker 参数基线（可复现）。

---

## P5 · 端到端时延预算（与 P1 并行）

**任务与目的**：全链逐段计时，对照部署帧率要求，确定轻量档准入下限——时延超标则定型无意义。

**Pipeline**：

1. **逐段计时**
   - 做什么：pillar 化 preproc → infer → NMS → tracker 逐段计时，各基准全覆盖
   - 符合：拿到完整时延分解表 → 进 step 2
   - 不符合：某段无法独立计时 → 先打点补测量，估算值标注「估算」

2. **对照预算**
   - 做什么：时延分解 vs 部署帧率要求
   - 符合：基准满足要求 → 完成
   - 不符合：超标 → 定位瓶颈段反馈 P1（换轻量候选 or 结构减负）

**阶段出口预期**：时延分解表 + 轻量档准入下限。

---

## 汇总

定型决策包 = 基准定稿 + 过拟合/泛化证据 + 误差模型 + tracker 指标 + 时延预算。每阶段独立报告，最终一页汇总。
