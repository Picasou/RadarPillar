# 部署链路环境审计（pth → xmodel → 板端 C）

2026-09-15 对「训练权重 → ONNX/Vitis AI → .xmodel → 板端 C 工程」全链的代码/本机环境/官方生态审计。与 [ZU3EG_部署评估与方案.md](ZU3EG_部署评估与方案.md)、[ZU5EV_部署评估与方案.md](ZU5EV_部署评估与方案.md) 配套（两文已按本审计勘误）；§7 执行顺序已展开为 [部署仿真工程计划_20260915.md](部署仿真工程计划_20260915.md)。官方证据快照：[vai_refs_20260915/](vai_refs_20260915/)。

## 1. 链路定案

- 官方主路径 `vai_q_pytorch` 直接吃 .pth（量化 → export xmodel → `vai_c_xir` 编译），ONNX（`vai_q_onnx`）为备选路径，二者选一冻结即可
- **整模型不可导出**（batch_dict 字典流 + `.item()` 控制流 + 动态 pillar 数 + MHA/LayerNorm/GELU/scatter/NMS 均 DPU 不支持），按已冻结拆图边界三段部署：
  - **CPU**：pillar 化 + PillarVFE + PillarAttention + scatter（C++ 手写）
  - **DPU**：BaseBEVBackbone + head conv 栈，输入 `[1,32,80,200]`，输出 `[1,12,40,100]`（hm4+reg2+height1+dim3+rot2）
  - **CPU**：decode（sigmoid/exp/atan2）+ NMS
- .xmodel 只能上板跑（DPU+VART），PC 无法直接执行；PC 侧验证用 onnxruntime 对拍 ONNX，上板前可先借官方板（ZCU102/104/KV260）验证模型再回自有板

## 2. 导出对象

- 主候选 `msr_centerhead3d_trunk`：`output/train_log/msr/202608210351_rpillar_msr_centerhead3d_trunk_.../best.pth`（3D 88.13 / BEV 87.33 / 0.27M），**cfg 用同目录快照**（与训练时严格一致）
- msrv2 批次为泛化口径（BEV 30~50），不作首轮导出对象
- 仓库唯一可复用轮子：`tools/utils/visual_utils/visualize_architecture.py` 的 `BevBackboneHeadWrapper`——切分接口与拆图方案吻合，但用随机权重，需自行接 ckpt

## 3. 版本矩阵（定案）

- 编译侧统一 **Vitis AI 5.0**（`xilinx/vitis-ai-pytorch-cpu:latest`，2026-02 发布，量化编译无需 GPU）；`vai_c_xir` 编译，arch 用容器内置 DPUCZDX8G arch.json 或 FPGA 侧交付的工程 arch.json
- DPUCZDX8G **IP 冻结 v4.1**（VAI3.0/2022.2 起 RTL 不再更新；「停更于 4.1」指 IP 版本号，不存在 Vitis AI 4.1）；IP 冻结 ⇒ arch.json 对 VAI3.0~5.0 的 vai_c 通用
- 板端 VART 必须与编译侧同代（跨代拒载 xmodel）；**无预编译板卡镜像**（官方只到 ZCU102/104/KV260 且止于 v3.0）→ 自定义板必自建 Petalinux
- Vivado 官方验证矩阵最高 2025.1；本机 2025.2 超一格 → FPGA 侧先试开 IP 包（`DPUCZDX8G_VAI_v3.0.tar.gz`，download.amd.com 直连可达，实测 83MB/200）定案，不行降 2025.1

## 4. 环境缺口（PC 侧）

- **导出段**：conda base（py3.12 / torch2.4.1+cu124）缺 onnx/onnxruntime（pip 装）；导出脚本从零写（改造 BevBackboneHeadWrapper + 接 ckpt + allclose 对拍）
- **量化编译段（最大缺口）**：WSL2 无 docker（无 Docker Desktop/docker-ce；systemd 已启用，apt 装 docker-ce 即可）；**registry-1.docker.io 直连不可达** → 注册型 mirror（docker.1ms.run 实测可达，配 daemon.json + login）或海外机器 docker save/load；免 docker 路线无官方支持（conda 通道 404）
- **交叉编译段**：apt 装 gcc-aarch64-linux-gnu + cmake（apt 通道实测畅通）；正式 sysroot = PetaLinux SDK（`sdk-*.sh` + `vitis_ai_*.tar.gz` 增量包，含预编译 VART 头/库），Windows 侧 Vitis 2025.2 自带 aarch64 工具链仅作备选
- 磁盘：WSL 根 910G 可用（镜像 >20G 无压力）；/mnt/c 仅剩 28G 勿放镜像/工程

## 5. 关键风险与勘误

- **B400 为笔误**：VART 目标库 DPUCZDX8G 档位 512/800/1024/1152/1600/2304/3136/4096，无 B400 → 3EG 应为 **B512**（PG338 定档核实）
- **GFLOPs 口径**：5.49G 为 resbag thop **bs=4** 口径，单帧 conv 段实际 ≈1.37 GFLOPs（≈0.69 GMACs）→ DPU 段很轻，性能风险重心在 CPU 前段+后处理；软跑复算约 3~5 FPS（排除结论不变，余量比旧记载数倍）
- **attention 一票否决项**：真实非空 pillar mean 341 / p99 533 / max 627；若静态 pad 到 MAX_VOXELS=3096 进图，MHA 计算量暴涨 ~60×（score 矩阵 38MB DDR 往返）→ 板端必须 CPU **true-N 动态实现 + NEON**（全链预算 ~10-30 ms/帧可达成 15-30Hz；纯标量 10Hz 边缘）；GELU 用 `erff()` 对齐 PyTorch exact 式
- **ConvTranspose2d**：deblock 的 k=stride/p=0 写法经 nndct `dpu_op_filter.py` 源码证据链判断可落 DPU，但须先做单算子最小子图试编译（B512/B1600 各一遍）再写完整导出脚本；兜底为 k=s 严格等价 nearest 上采样+Conv2d 图手术，零重训
- **INT8 硬门槛**：PTQ calib 100~1000 帧，掉点 ≤1~2pt（MSR eval 同 R40 口径）；兜底 per-channel → 敏感层 FP16 → QAT
- repdwc 系候选导出前必须 reparam 融合（`tools/test.py` 的 `apply_reparam_if_rep` 现成）

## 6. C 工程形态（板端）

- 骨架仿 Vitis-AI `examples/vai_runtime/resnet50`：`xir::Graph::deserialize` → `get_dpu_subgraph` → `vart::Runner::execute_async/wait`；含 CPU 子图用 GraphRunner
- 链接 `-lvart-runner -lxir -lunilog -lglog`；交叉编译前 source SDK 的 `environment-setup-cortexa72-cortexa53-xilinx-linux`
- Petalinux：开 DPU kernel driver、**排除 zocl/xrt**（Vivado 流）、`recipes-vitis-ai`（VART 用 vivado 版 recipe，如 `vart_3.5_vivado.bb`，否则运行时加载报错）、CMA 默认 256M 必要时 bootargs 调大
- 两核分工：核1 前段+DPU 喂数，核2 decode/NMS/tracker（isolcpus + SCHED_FIFO）
- 先例：官方 PointPillars 的 PPScatter 即 CPU custom op（`examples/custom_operator`）；本项目拆图方案下无需 custom op

## 7. 执行顺序

1. pip install onnx → 导出脚本（wrapper 接 best.pth）→ allclose 对拍
2. 装 docker + mirror → pull 镜像 → **ConvTranspose 最小子图试编译** → 全 DPU 段 dry-run 出 CPU 回退层清单
3. 并行 FPGA 侧：2025.2 试开 IP 包 → block design 集成（与功能 A 共存）→ 拿 arch.json
4. PTQ 量化 + INT8 mAP 对拍
5. sysroot → C 工程（resnet50 骨架 + CPU 前段/后处理 C++）
6. Petalinux 自建（与 5 并行）
