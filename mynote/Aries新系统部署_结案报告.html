三、推理链

翻案 1

E17：官方 mkimage FIT = 6.6 完整启动

板/内核/XSA 全部无辜；15 连死真凶 = dtc 手拼 FIT（老 u-boot 把镜像头当设备树递给内核）。

翻案 2

"板不兼容 6.6"结论作废

final1/5/6/7 均跑起 6.6 到 systemd/登录；rootfs p2 实测 r/w 挂载成功。

串口

控制台与雷达数据共用一根线

FT232 交叉接法可收发；u-boot 全文、内核日志、PHY 状态全部可见。

网卡 MAC 层

mii + fixed-link → Link Up 100M/Full

但 fixed-link 是虚拟 PHY（不查真硬件）——MAC 说通了，物理线没通。

物理数据路

ARP 零应答、MDIO 无设备

MAC 走 EMIO（FPGA 绕道）而板上电线接在 MIO 直连——两边说的不是同一条路。

PHY 复位 GPIO

老系统 402/403 vs 6.6 内核 base=580

编号映射未确定（尝试 658/659 = EMIO 0/1 无效；可能不在 EMIO 而在 PL GPIO 或 MIO）。

同事建议

用老系统一样的 DTB + user_setup.sh

方向正确（老 DTB 配 MIO/mii 与老 BOOT.BIN 配套）但老 DTB 在 6.6 下可能不兼容（final10 串口无内核输出）。

  • ✓ 内存盘嵌入前剥 64 字节 u-boot 头

五、网卡修复的三条候选路径

路径 A：FPGA 改 XSA

ENET3 从 EMIO 改回 MIO 64-77，重导 XSA → 我全量重编 → 一次交付。

最正确；需 FPGA 同事在 Vivado 改一个选项。

路径 B：GPIO 扫描

在已跑起的系统里逐个试 GPIO 编号释放 PHY 复位，让 MDIO 找到 PHY。

已试 658/659(EMIO 0/1) 无效；老系统 402/403 映射未确定。

路径 C：mii 无 fixed-link

去掉 fixed-link，内核在 MDIO 上找真 PHY。老 FSBL 可能已释放 PHY → 直通。

final11 已备好待上板。

六、FPGA 侧一句话任务

Vivado 打开 a1 → 把 PS 的 ENET3 从 EMIO 改回 MIO 64-75 + MDIO 76-77（对齐老系统已验证布线；顺带 UART0 从 MIO 74/75 改回 42/43），勾 Include bitstream 重导 XSA。
