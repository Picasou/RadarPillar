# PTQ（训练后量化）方法族简释  

> PTQ = 训练完的模型直接压成 INT8，不碰训练。量化误差来源有五个，各有一族修法。每节统一按「有什么问题 → 为什么这样做 → 哪些方法 → 我们的档位」展开。  

## 总纲：这一切的目的是什么（先读这节）

1. **为什么必须量化**：模型要跑上板，板上的加速器 DPU 只吃 INT8——fp32 模型不压就上不了板。量化不是可选项，是上板的入场券  
2. **量化的代价**：INT8 只有 256 个格子表示原本连续的数值，"压"必然引入误差——落到结果上就是检测框变差（漏检、误检、分数漂移、框位置偏）  
3. **所以全部 PTQ 方法的共同目的**：在"必须压"的前提下，把压的代价压到最低——目标是压完检测精度几乎不掉（MSR eval AP 掉点 ≤1~2 分）  
4. **怎么达到**：误差有五个来源（离群值 / 通道差异 / 数据见闻少 / 层间不均 / 个别层敏感），每个来源一族修法——即本文五节；五招用尽仍不行，最后让模型自己适应（QAT，档5）  

## 1. 校准方法  

**有什么问题**：定数值范围的统计量若被离群值绑架——某层一个值冲到 50、其余都在 ±1——range 被撑爆，其他数全挤进 int8 的几个格子，精度暴跌。  

**为什么这样做**：scale 由 range 决定，range 是从数据统计出来的；统计量选得抗离群，range 才贴近真实分布的主体。  

**哪些方法**：  

- maxmin：取最大绝对值——最简单，最怕离群点  
- percentile：砍掉最大 0.1% 再取 max——离群点不再捣乱  
- entropy（KL 散度，TensorRT 经典）：搜一个截断点使量化前后分布差异最小  
- MSE：搜使重建误差最小的截断点  

**量化谁**：激活（quant_info.json 的 output 段）——喂数据统计的就是激活范围，抗的离群也是激活的离群。

**我们的档位**：现状 maxmin（`qcfg_maxmin.json` 的 `"method"` 字段）；entropy/percentile 为备用旋钮。  

## 2. 量化粒度  

**有什么问题**：一层卷积 [64,32,3,3] 共 18432 个权重共用一个 scale 时，63 个通道在 ±1、1 个通道冲到 ±10——scale 只能按 10 定（≈0.079/格），0.5 的值量化后只剩 6 个格子，分辨率浪费 10 倍。  

**为什么这样做**：数值范围差异发生在**通道之间**，就把 scale 的管辖权按通道切开——每通道各定各的，各自把 -128~127 用满。类比：合租一个电表改每户自己装表，大户不再让小户跟着"平均高价"。  

**哪些方法**：  

- per-tensor：整层一个 scale（现状）  
- per-channel：每输出通道一个 scale（卷积权重标配做法）  
- per-block / 更细：分组定 scale（更稀有的做法）  

**量化谁**：权重（param 段）——"每通道"切的就是权重张量 [64,32,3,3] 的 64 个输出通道；激活通常仍整层一个 scale。

**我们的档位**：**档1**——改设置即可，梯子第一刀，收益通常最大。  

## 3. 校准数据量  

**有什么问题**：50 帧估的 range 没覆盖全部场景——更密的点、更强的回波上板一遇，数值超出预估范围直接被**截断**（clipping），精度当场崩。  

**为什么这样做**：scale 本质是统计量，统计精度随样本量上升；样本覆盖的场景越全，range 越稳。类比：民调问 50 人 vs 问 1000 人。多拿的数据不是新采集——是训练集已有的帧多跑一遍前段、存下 DPU 段输入（`calib_dump.py` 干的事）。  

**哪些方法**：  

- 加帧数：50 → 256 → 1024（官方建议 100~1000）  
- 挑代表性：按场景多样性抽样，而不是纯随机  

**量化谁**：激活——喂出来的样本全是激活样本，攒的是激活分布。

**我们的档位**：**档2（256 帧）/ 档3（1024 帧）**。  

## 4. 压前图优化  

**有什么问题**：①层间数值分布不均——有的层范围爆表、有的太窄，同一套 int8 格子对各层"宽松度"差别巨大；②量化舍入有系统性偏差（round 老往一边偏），输出整体偏移。  

**为什么这样做**：两类都是**数学等价变换**——压之前把网络换个写法，输出一个比特不变，但每层都落进舒服的量化区间。  

**哪些方法**：  

- CLE 跨层均衡：conv→ReLU→conv 链上，第一层输出统一乘 2、第二层权重统一除 2——结果不变，范围从"爆表层"匀给"太窄层"。类比：一杯满一杯浅，先倒匀再分  
- bias correction：压完在每层 bias 上加补偿量抵消系统偏移。类比：秤总偏 5 克，读数统一减 5 克  

**量化谁**：激活——CLE 匀的是层间激活范围，bias corr 修的是激活输出的系统偏移。

**我们的档位**：`include_cle: true`、`include_bias_corr: true`——**已默认开启**，不占档位。  

## 5. 混合精度  

**有什么问题**：网络里常有 1~2 层对量化极其敏感（预期是 hm 头附近卷积），压了它们全局遭殃——病不在全体，在个别层。  

**为什么这样做**：既然病在个别层，只救个别层的收益/代价比最高：敏感层保高位宽，其余照压 INT8，整体几乎不损失速度。  

**哪些方法**：  

- 逐层误差分析（量化前后输出差）排序，取 top-K 敏感层  
- 敏感层保持 FP16 / 改 16bit 位宽（DPU 对 16bit 的支持形态在 T1 探测时确认，落法按实测）  

**量化谁**：权重、激活皆可——逐层误差分析指哪保哪（param 或 output 条目）。

**我们的档位**：**档4**——落点就是 `quant_info.json` 名单里把敏感层的 `[[8,7]]` 改掉。  

## 全景：病 → 药 → 档位  

```
离群值(激活)  → 校准方法(entropy/percentile)  → 备用旋钮
通道差异(权重) → per-channel                   → 档1
见闻少(激活)   → 校准数据加量                  → 档2/3
层间不均(激活) → CLE + bias corr               → 已默认开
个别层敏感(皆可) → 混合精度 FP16                 → 档4
权重不适噪声     → QAT 短训                      → 档5（这就不是 PTQ 了）
```

- 五种修法互相独立、可叠加；梯子按性价比排序：免费设置（1/2/3）→ 动结构（4）→ 上训练（5）
